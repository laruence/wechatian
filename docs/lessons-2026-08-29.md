Lessons — 2026-08-29 outage: the 412 saga
==========================================

One perf commit broke WeChat message delivery for an hour. Five commits and
two wrong diagnoses later it was fixed. This records what actually happened
and the rules that would have short-circuited it.

Timeline
--------
1. 2a6153a (perf batch) moved ALL gateway traffic from ObsidianTransport
   (requestUrl) onto NodeTransport (node http/https) to avoid IPC overhead.
2. 09:42 Obsidian auto-updated and restarted; the plugin's first poll got
   HTTP 412 from ilink/bot/getupdates and retried it forever. Status bar
   stuck on "error". User's WeChat message queued server-side, never landed.
3. Diagnosis went in circles: manual replays returned 200, so we assumed the
   stored cursor/session was fine, then suspected iCloud, then dual-device.
   Two wrong fixes shipped (9d52fa0: 412 = re-scan; e1054d3: 412 = clear
   cursor). Neither helped — after the cursor reset the loop stuck on
   "connecting" because the re-poll 412'd too.
4. Rollout rollback (deploy main.js from 8a85908) restored service at once.
5. The decisive replay: same body, same headers, same cursor —
     node http/https module  -> 412 every time
     fetch (undici)          -> 200 every time
   The gateway TLS-fingerprints the HTTP client. Node's ClientHello is
   rejected outright; Chromium-class stacks pass. Headers are irrelevant:
   UA, Accept, Accept-Encoding, Connection, header case, even removing
   Content-Type — all still 412.
6. Fix d732cb8: gateway + CDN traffic back on requestUrl; NodeTransport kept
   only for article fetches (mp.weixin.qq.com does not fingerprint, and its
   real abort/idle timeout protects against slow-drip there). Plus 0268439:
   exponential backoff (2s -> 30s cap) on repeated 412 cursor resets.

Root cause
----------
ilink (and very likely the whole weixin.qq.com edge) rejects Node-core HTTP
clients at the TLS layer. Any feature work that moves gateway traffic onto
node:http/https — no matter how well-intentioned — will 412-loop.

Rules (the part worth remembering)
----------------------------------
1. NEVER route ilink gateway or CDN traffic through NodeTransport.
   It is for third-party web pages only. (Enforced by comments in
   src/main.ts, src/core/transport-node.ts, docs/ilink-protocol.txt —
   if you ever revisit the IPC-perf argument, re-read this file first.)

2. Replay experiments must use the SAME stack as production code. The
   "replay works, so the server is fine" inference was the hour-sink:
   fetch (undici) passes the fingerprint, node http does not. When a
   node-based tool disagrees with the app, suspect the tool, not the app.

3. Distinguish "session expired" from "client rejected" before writing a
   recovery path. 412 here meant neither what we first coded:
     412 = client/cursor rejected -> reset cursor, back off, keep session
     401/403 = credentials bad    -> QR re-scan
   Retryable-by-default (the old behavior) silently 412-loops; expiry-by-
   default (first fix) forces useless re-scans.

4. Every retry/reset path needs a wait BEFORE this commit-style incident
   recurs: the cursor-reset branch originally had none, so a persistent 412
   hot-looped and looked like "stuck on connecting". All error branches of
   the poll loop now sleep (error backoff, reset backoff, expiry pause).

5. Rollback first when a deployed change breaks a live service: restoring
   main.js from the last known-good commit took 10 seconds and proved the
   diff was the cause, ending all speculation at once.

6. Auto-updating app + plugin = the release trigger. The change had been
   sitting in the vault since the morning build, inert until Obsidian's
   09:42 auto-update restart loaded it. "It broke when you opened the app"
   can be true even when the code changed hours earlier.

Verification checklist for transport changes (from now on)
----------------------------------------------------------
- [ ] node --test (unit) passes
- [ ] replay one real poll AND one real send through the exact production
      transport class (not fetch), confirm 200
- [ ] deploy to vault, reload Obsidian, status bar shows online
- [ ] send a real WeChat message, confirm it lands in the daily note
